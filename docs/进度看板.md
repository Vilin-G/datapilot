## 四、卡点与已知风险

- 两表 2010-12-01 ~ 2010-12-09 完全重复 → **已处理**（删除表2重复段），诊断见 `scripts\02_check_overlap.py`
- **SQLite 使用细节**：
  - 列名 `Customer ID` 带空格，SQL 里必须写成 `"Customer ID"`
  - `Customer ID` 是 REAL 类型（因为该列有缺失值），整数显示成 `13085.0`
  - `sqlite3.connect()` 传目录或错文件名都不报错，前者打不开、后者静默建空库
  - `execute()` 一次只接受一条语句，"分号拼接"会被数据库自己挡住（但这是数据库的护栏，不是我们的设计）
- `run_sql` 的只读校验是"字符串检查开头"，**不是真正的安全边界**；真正的做法是以只读方式打开连接（`mode=ro`），留到后面再优化
- 待验证：表内是否存在合法的整行重复
- 后续站点要处理的数据问题：`Description` 缺失 4,275；`Customer ID` 缺失 235,287（约 22.5%）；`Quantity` 为负 = 退货；`Invoice` 以 `C` 开头 = 取消单；`StockCode = POST` 等非商品行
