## 四、卡点与已知风险

- 两表 2010-12-01 ~ 2010-12-09 完全重复 → 已处理；诊断脚本见 `scripts\02_check_overlap.py`
- **SQLite 使用细节**：
  - 列名 `Customer ID` 带空格，SQL 里必须写成 `"Customer ID"`
  - `Customer ID` 是 REAL 类型（因该列有缺失值），整数显示成 `13085.0`
  - `sqlite3.connect()` 传目录或错文件名都不报错，前者打不开、后者静默建空库
  - `execute()` 一次只接受一条语句
- `run_sql` 的只读校验是字符串检查，**不是安全边界**
- **数据质量问题（第二站之后要处理）**：`Description` 缺失 4,275；`Customer ID` 缺失 235,287（约 22.5%）；`Invoice` 以 `C` 开头 = 取消单；`M` / `DOT` / `POST` 等非商品代码会污染商品维度分析
- **⚠️ 退货口径（2026-11-09 定稿评测集时查实，纠正旧说法）**：本库**没有"普通退货"**。负数量行 22,557 条，其中 19,164 条属 `C` 开头发票（Price 全 > 0，金额 -1,465,677.23），另 3,393 条非 C 负数量行 **Price 全是 0**（库存报损：`given away` / `printing smudges` / `damages` / `invoice 506647`）。**结论：取消单就是退货，退货金额用 `ABS(SUM(Quantity*Price)) WHERE Invoice LIKE 'C%'`，不用 `Quantity < 0`。** 旧说法"退货 = Quantity < 0，与取消单是两回事"已作废
- **非商品代码完整清单**（做商品维度必须排除）：`M` / `DOT` / `POST` / `BANK CHARGES` / `C2`(CARRIAGE) / `D`(Discount) / `S`(SAMPLES) / `ADJUST` / `ADJUST2` / `AMAZONFEE`(单价 6822.6，会把平均售价榜污染) / `B`(bad debt) / `CRUK`(佣金) / `PADS` / `TEST001` / `m`
- **6 张 `A` 开头发票**（`Adjust bad debt`，合计 -147,614.08，含一笔 +11,062.06）既不在 C 单口径内也不在正向口径内，现有评测题均未覆盖
- 待验证：表内是否存在合法的整行重复
- **`DASHSCOPE_API_KEY` 是占位符**（2026-10-26 实测 401 `invalid_api_key`）：`.env` 里值被误写成变量名本身。项目一（`Own_project_NO1_v1`）同样是占位符，只有 `L3_DAY_2_v1` 里有真 key（但也是 `sk-xxx` 形式的样例值）。**2026-11-09 已放弃这条路，改 DeepSeek，详见"进行中"的环境说明**
- **`langchain` 主包没装也不需要**：新版 `@tool` 装饰器在 `langchain_core.tools`，装了主包反而可能拉进冲突版本
