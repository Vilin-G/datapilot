## 四、卡点与已知风险

- 两表 2010-12-01 ~ 2010-12-09 完全重复 → 已处理；诊断脚本见 `scripts\02_check_overlap.py`
- **SQLite 使用细节**：
  - 列名 `Customer ID` 带空格，SQL 里必须写成 `"Customer ID"`
  - `Customer ID` 是 REAL 类型（因该列有缺失值），整数显示成 `13085.0`
  - `sqlite3.connect()` 传目录或错文件名都不报错，前者打不开、后者静默建空库
  - `execute()` 一次只接受一条语句
- `run_sql` 的只读校验是字符串检查，**不是安全边界**
- **数据质量问题（第二站之后要处理）**：`Description` 缺失 4,275；`Customer ID` 缺失 235,287（约 22.5%）；`Quantity` 为负 = 退货；`Invoice` 以 `C` 开头 = 取消单；`M` / `DOT` / `POST` 等非商品代码会污染商品维度分析
- 待验证：表内是否存在合法的整行重复
