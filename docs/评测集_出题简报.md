# 评测集 · 给 AI 的出题简报

> 用途：把下面「分隔线之后」的整段内容原样粘给 AI，让它出题。  
> 出题后**不要**用它的答案当标准答案——标准答案必须在本机真库上跑出来。

---

## 你是一个数据评测题设计师

我有一个 SQLite 数据库，里面是英国一家在线零售商 2009-12-01 到 2011-12-09 的销售明细。我要用它来评测一个「能自己写 SQL 查库」的 AI Agent，需要你帮我出 **14 道**自然语言问题。

**你先别急着出题，先读完下面的数据说明和口径陷阱。**

## 一、表结构

只有一张表 `orders`，1,044,848 行，8 个字段：

| 字段            | 类型        | 含义                                                      |
| ------------- | --------- | ------------------------------------------------------- |
| `Invoice`     | TEXT      | 发票号。**一张发票 = 一个订单**。以 `C` 开头表示取消单                       |
| `StockCode`   | TEXT      | 商品代码                                                    |
| `Description` | TEXT      | 商品名（可能为空）                                               |
| `Quantity`    | INTEGER   | 数量。**负数 = 退货**                                          |
| `InvoiceDate` | TIMESTAMP | **实际存的是 TEXT**，格式 `2009-12-01 07:45:00`                 |
| `Price`       | REAL      | 单价                                                      |
| `Customer ID` | REAL      | 客户编号。**有空格，SQL 里必须写 `"Customer ID"`**。可为空，显示成 `13085.0` |
| `Country`     | TEXT      | 国家                                                      |

**真实样例（前 3 行）：**

```
489434 | 85048  | 15CM CHRISTMAS GLASS BALL 20 LIGHTS | 12 | 2009-12-01 07:45:00 | 6.95 | 13085.0 | United Kingdom
489434 | 79323P | PINK CHERRY LIGHTS                  | 12 | 2009-12-01 07:45:00 | 6.75 | 13085.0 | United Kingdom
489434 | 79323W |  WHITE CHERRY LIGHTS               | 12 | 2009-12-01 07:45:00 | 6.75 | 13085.0 | United Kingdom
```

## 二、数据统计（已实测）

- 明细行数：**1,044,848**
- 订单数（`COUNT(DISTINCT Invoice)`）：**53,628**
- 客户数（`COUNT(DISTINCT "Customer ID")`）：**5,942**
- 商品数（`COUNT(DISTINCT StockCode)`）：**5,305**
- 国家数：**43**，其中英国占 **91.6%**（49,108 张订单）
- 日期范围：**2009-12-01 ~ 2011-12-09**
- **两段数据不等长**：2009-12 到 2010-12 约 374 天，2010-12 到 2011-12 约 365 天

## 三、口径陷阱（出题必须绕开或明确写清）

1. **销售额** = `SUM(Quantity * Price)`。表里**没有**「金额」字段，也没有成本、利润、折扣字段。
2. **退货** = `Quantity < 0`。含退货与不含退货的销售额能差 **7.75%**（退货金额 -1,465,677.23，总销售 18,909,762.12）。**任何销售额类题目都必须写明含不含退货。**
3. **取消单** = `Invoice` 以 `C` 开头。这类单的 `Quantity` 也是负数，和普通退货混在一起。
4. **非商品代码**：`M`（手工调整）、`DOT`（邮费）、`POST`（邮费）、`BANK CHARGES`（银行手续费）。它们有 `Quantity` 和 `Price`，但**不是商品**，做商品维度排行时必须排除，否则排行会被污染。
5. **`Customer ID` 可为空**。算客户维度时必须加 `WHERE "Customer ID" IS NOT NULL`，否则会多出一个「匿名客户」。
6. **`InvoiceDate` 是 TEXT**，比较用字符串就行（`>= '2011-11-01' AND < '2011-12-01'`），因为 `YYYY-MM-DD HH:MM:SS` 的字典序就是时间序。
7. **两段数据不等长**，所以「2010 年 vs 2011 年」这种同比题必须说明是整年还是自然段，否则没有可比性。

## 四、我要什么样的题

**正好 50 道**，按下面四层分布（我会从里面挑一部分定稿）：

| 层级          | 含义               | 要几道 | 例子方向                     |
| ----------- | ---------------- | --- | ------------------------ |
| **L1 简单**   | 单表一次聚合，一问一答      | 23% | 总行数、订单数、客户数              |
| **L2 过滤**   | 要加时间/国家/非空等条件    | 23% | 2011-11 的订单数、除英国外订单最多的国家 |
| **L3 口径陷阱** | 不写清口径就会算错        | 50% | 销售额最高月份、退货率、商品销量排行       |
| **L4 无解**   | **数据库里根本没有这个信息** | 2 道 | 利润、满意度、客户年龄、商品分类         |

### 每道题请给我这些

```
题号 + 中文问题（一句自然人话，像业务同事问你的那样）
难度层级（L1/L2/L3/L4）
口径说明（这题涉及哪些陷阱、必须怎么定义）
你打算用的 SQL（给 L1~L3；L4 不用给）
预期答案形态（一个数字 / 一个 TOP 5 列表 / 一句"库里没有"）
```

### 硬性要求

- **L1~L3 的每道题，答案必须唯一**。并列第一的情况要提前说明怎么处理（比如「并列时都列出」）。
- **L3 的题不能只靠猜口径**：如果这题含退货和不含退货会有两个不同答案，你必须在口径说明里明确指定用哪个。
- **L4 的题必须是真的无解**：表里连间接推出来的可能都没有。
- **问题要像人话**，不要写成 SQL 的翻译。反例："请用 SUM 函数对 Quantity 和 Price 的乘积求和"。正例："哪个月卖得最好？"
- **避免所有题都问「最高/最多」**。要混一些「有多少」「占比多少」「平均多少」「趋势怎么样」。

### 不要出这些题

- 需要多表 JOIN 的（只有一张表）
- 需要外部知识或行业常识的（比如「这个商品属于哪个品类」）
- 「哪两个客户最像」这类无法用 SQL 验证的

## 五、最后

出完50道题后，**额外用一段话告诉我**：你觉得哪几道最容易被 AI 答错，为什么。我要用这个来预判评测结果。
