### 2.3 怎么在脚本里拿 key

```powershell
# PowerShell 里跑脚本前，把机器级环境变量搬进当前进程
$env:DEEPSEEK_API_KEY = [Environment]::GetEnvironmentVariable('DEEPSEEK_API_KEY','Machine')
```

```python
import os
api_key = os.environ["DEEPSEEK_API_KEY"]   # 不要 load_dotenv 指望它读到
```

**⚠️ 不要把真 key 写进 `.env` 或任何会被提交的文件。** `.env` 已进 `.gitignore`，但保持占位符状态更安全——直接读环境变量。

## 4. 我们的打算：两三天冲刺版

### 4.1 为什么改计划

用户在求职中，投了约 20 家 0 面试，最缺的是**一个能拿出手、面试讲得清的完整项目**，不是四站全做完。

### 4.2 范围（做什么 / 不做什么）

**做：**
1. 第二站 第 2 小块：真调模型，让它自己决定调哪个工具、传什么参数
2. 第二站 第 3 小块：SQL 报错回传给模型，让它自我修正
3. 第二站 第 4 小块：最大调用次数，防死循环
4. 第四站缩减版：10 道评测题 + 完成率数字 + README

**不做（明确砍掉）：**
- 第三站多智能体（LangGraph Supervisor）—— 时间不够，且和 DeepResearch 项目重复
- 第四站的网页/前端 —— 只留 FastAPI 的一个接口，或者干脆跳过接口，评测直接用命令行跑
- 部署、并发、可观测性

### 4.3 三条"做够就停"的标准

做到这三条就宣告完成，不再往里加东西：

1. **模型能自己查数**（问一句话，它自己调工具、拿数据、给出带数字的回答）
2. **有 10 道评测题 + 一个完成率数字**（能说"10 题里过了 7 题，失败的是因为有 3 题需要跨表/口径歧义"）
3. **能讲清一条取舍**（比如"为什么用 SQLite 不用 MySQL""为什么工具返回 JSON 不返回自然语言"）

### 4.4 执行顺序（不要按大纲顺序，按这个）


**关键：不要在第 2 天做第三站。** 拿到评测数字比多一个智能体值钱。

## 7. 已知坑（会静默出错的那种）

1. **`truncated=False` 不等于"数据完整"** —— `run_sql` 会自动给没有 LIMIT 的 SQL 补 `LIMIT 100`，那 100 行是从 104 万行里截的，但 `truncated` 只看 Python 切片那一刀，所以照样报 `False`。**等模型真跑起来它会自己暴露**，那时再改（改成"SQL 里补了 LIMIT 也算 truncated"）。
2. **`Customer ID` 带空格** —— SQL 里必须写 `"Customer ID"`，不带引号直接语法错。这正好是测试"报错自我修正"的好素材。
3. **`Customer ID` 是 REAL** —— 因为该列有缺失值，整数显示成 `13085.0`。
4. **`run_sql` 的只读校验只是字符串检查** —— `sql.strip().upper().startswith("SELECT")`，不是安全边界。靠 SQLite `execute()` 一次只执行一条语句兜着。
5. **一张发票 = 一个订单** —— 数订单用 `COUNT(DISTINCT Invoice)`；行数（1,044,848）是明细行数，不是订单数（53,628）。这个口径不说清，评测题会判错。
