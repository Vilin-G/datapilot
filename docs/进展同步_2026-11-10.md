## 三、第二站的验收证据（可直接写进简历/面试讲）

**报错回传不是一个功能，而是"不要吞掉"的结果。** `messages.append({"role":"tool","tool_call_id":tc.id,"content":result})` 原样塞回，`result` 是错误就自动变成纠错线索。

为了证明它真的生效，做了个实验：**把 `describe_database` 从工具列表里拿掉**，让模型看不到 schema。实测 6 步：

```
[1] SELECT name FROM sqlite_master WHERE type='table'      ✅
[2] SELECT * FROM orders LIMIT 5                           ✅ 偷看数据
[3] SELECT CustomerID, SUM(Quantity*UnitPrice) ... FROM orders
    → {"ok": false, "error": "no such column: CustomerID"}  ❌ 一次错两个词
[4] SELECT * FROM pragma_table_info('orders')              ← 自己查真实列名
[5] SELECT "Customer ID", SUM(Quantity*Price) ...          ← 改对
[6] 答案：客户 18102，570,380.61
```

本地手写 SQL 对账：完全一致。

**教学上的教训**：验收项如果"自然发生不了"，就主动构造让它必然发生的条件——拿掉一个工具比反复换问题有效得多（复盘手册第 17.2 条）。

### 重大口径发现：这个库里没有「普通退货」

扫全库负数量行（22,557 条）：

| 类型 | 行数 | Price | 金额 |
| --- | --- | --- | --- |
| `C` 开头发票（取消单） | 19,164 | **全部 > 0** | **-1,465,677.23** |
| 非 `C` 发票的负数量 | 3,393 | **全部 = 0.0** | **0.0** |

**顾客退货全部走 `C` 单。** 那 3,393 条非 C 负数量行价格全为 0，是库存报损（`given away` / `printing smudges` / `damages` / `invoice 506647`）。

**结论：取消单就是退货。** 退货金额必须用 `ABS(SUM(Quantity*Price)) WHERE Invoice LIKE 'C%'`，不能用 `Quantity < 0`。之前写在简报里的"退货 = `Quantity < 0`，与取消单是两回事"是错的，已在 `docs\评测集.md` 和看板里更正。

### 一个设计决定：口径写进问题文本

模型评测时只看到问题，看不到「口径说明」。同一问题两种口径数字不同：

```text
消费金额最高的客户：含取消单 570,380.61 / 不含 580,987.04
```

排名不变但数字变了，模型答 B 判 A 就是冤判。所以 10 道题的问题文本里直接写"不算退货和取消单的话……"，像业务同事说话，同时保证答案唯一。
