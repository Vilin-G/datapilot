## 二、重大发现：这个库里没有「普通退货」

扫全库负数量行（22,557 行）：

| 类型 | 行数 | Price | 金额 |
| --- | --- | --- | --- |
| `C` 开头发票（取消单） | 19,164 | **全部 > 0** | **-1,465,677.23** |
| 非 `C` 发票的负数量 | 3,393 | **全部 = 0.0** | **0.0** |

**结论：顾客退货全部走 `C` 开头发票。** 那 3,393 条非 C 负数量行价格全是 0，是库存调整（`given away`、`printing smudges`、`damages`、`invoice 506647`），不是退货。

**后果：**
- 「退货」和「取消单」在这份数据里**不是两回事**，取消单就是退货。
- 任何「只算普通退货、不算取消单」的题，答案必然是 0。
- 我此前在出题简报里写的「退货 = `Quantity < 0`，和取消单是两个概念」**是错的**，已在此更正。

**修正后的退货口径**：退货金额 = `ABS(SUM(Quantity*Price)) WHERE Invoice LIKE 'C%'` = **1,465,303.66**。

# 五、定稿 10 道题

## L1 · 简单（2 道）

### Q1 · 数据总量

**问题**：我们这份销售明细一共有多少条记录？

- **难度**：L1
- **口径**：统计全部数据行，不去重、不过滤
- **标准答案**：**1,044,848**
- **对账 SQL**：

```sql
SELECT COUNT(*) FROM orders;
```

---

### Q2 · 客户总数

**问题**：这家零售商一共有多少个不同的客户？

- **难度**：L1
- **口径**：排除 `"Customer ID"` 为空的记录，按客户编号去重
- **标准答案**：**5,942**
- **对账 SQL**：

```sql
SELECT COUNT(DISTINCT "Customer ID") FROM orders WHERE "Customer ID" IS NOT NULL;
```

**陷阱点**：不写 `IS NOT NULL` 不会多算（SQLite 的 `COUNT(DISTINCT)` 忽略 NULL），但会让模型误以为要特殊处理。**这题真正的考的是能不能记住字段名带空格要加双引号。**

## L2 · 过滤（3 道）

### Q3 · 2011 年 11 月的订单量

**问题**：2011 年 11 月这个月，我们一共做了多少张订单？

- **难度**：L2
- **口径**：一张发票 = 一个订单，按 `Invoice` 去重；时间用字符串范围比较
- **标准答案**：**3,462**
- **对账 SQL**：

```sql
SELECT COUNT(DISTINCT Invoice) FROM orders
WHERE InvoiceDate >= '2011-11-01' AND InvoiceDate < '2011-12-01';
```

**陷阱点**：① 用 `COUNT(*)` 会得到 84,711（明细行数，不是订单数）；② 用 `LIKE '2011-11%'` 也能对，但用 `BETWEEN` 要小心边界（这里不含右端，`BETWEEN '2011-11-01' AND '2011-11-30'` 会漏掉 30 号当天有时分秒的记录）。

---

### Q4 · 英国以外订单最多的国家

**问题**（2026-11-12 修订，口径钉死）：除了英国，把所有发票都算作订单（取消单也算），哪个国家的订单数量最多？有多少张？

- **难度**：L2
- **口径**：按 `Invoice` 去重算订单，排除 `United Kingdom`；**不排除 C 单**
- **标准答案**：**Germany，1,095 张**
- **对账 SQL**：

```sql
SELECT Country, COUNT(DISTINCT Invoice) c FROM orders
WHERE Country <> 'United Kingdom' GROUP BY Country ORDER BY c DESC LIMIT 1;
```

**陷阱点**：用 `COUNT(*)` 会得到错误的排名顺序（明细行数和订单数不对应）。

**为什么改题干（实测证据见复盘 18.3）**：原题干没写"取消单算不算订单"。第 3 轮模型答「德国 789 张，已排除 C 开头取消单」——查库确认，排除 C 单后德国**正好 789**，全部发票是 1,095，**两种口径下德国都是第一**。它算对了，是我们没写口径。所以改成钉死"全部发票都算"。

**两种口径的实际数字**（第一名都是德国，只是张数不同）：

| 口径 | Germany | EIRE | France |
| --- | --- | --- | --- |
| 全部发票 | **1,095** | 806 | 746 |
| 排除 C 单 | 789 | 626 | 622 |

## L3 · 口径陷阱（4 道）

### Q6 · 销售额最高的月份

**问题**：不算退货和取消单的话，哪个月份的销售额最高？销售额是多少？

- **难度**：L3
- **口径**：销售额 = `Quantity * Price`；只算 `Quantity > 0`；排除 `Invoice LIKE 'C%'`；按 `SUBSTR(InvoiceDate,1,7)` 分月
- **标准答案**：
  - 第一名 **2011-11，1,509,496.33**
  - 第二名 2010-11，1,470,272.48
  - 第三名 2011-10，1,154,979.30
- **对账 SQL**：

```sql
SELECT SUBSTR(InvoiceDate,1,7) m, ROUND(SUM(Quantity*Price),2) s
FROM orders WHERE Quantity > 0 AND Invoice NOT LIKE 'C%'
GROUP BY m ORDER BY s DESC LIMIT 3;
```

**陷阱点**：含退货/取消单的算法会得到 1,461,756.25 —— **两个都"对"，取决于口径**。所以题面必须写"不算退货和取消单"。

### Q7 · 退货率

**问题**（2026-11-12 修订，口径钉死）：请只用发票号前缀区分：把发票号以 C 开头的记录的销售额总额（取绝对值）当作退货金额，把所有发票号不以 C 开头的记录的销售额总额当作正向销售额。退货金额占正向销售额的百分之多少？

- **难度**：L3（**这是本套评测最有价值的一题**）
- **口径**：
  - 分母 = 正向销售额 = 20,375,065.78（`Invoice NOT LIKE 'C%'`，**不额外过滤 Quantity**）
  - 分子 = 退货金额 = 1,465,303.66 = `ABS(SUM(Quantity*Price)) WHERE Invoice LIKE 'C%'`
- **标准答案**：**7.19%**
- **对账 SQL**：

```sql
WITH s AS (
  SELECT SUM(Quantity*Price) pos FROM orders WHERE Invoice NOT LIKE 'C%'
), r AS (
  SELECT ABS(SUM(Quantity*Price)) neg FROM orders WHERE Invoice LIKE 'C%'
)
SELECT ROUND(neg * 100.0 / pos, 2) FROM s, r;
```

**陷阱点（三重）**：
1. 用 `Quantity < 0` 当退货 → 分子 0，答案 0%（错得离谱）
2. 分子分母口径不一致（一个含取消单一个不含）→ 7.75%（看着很像对的）
3. 按数量算而不是金额算 → 完全另一个数

**为什么改题干（实测证据见复盘 18.3）**：原题干「顾客退货的金额，占我们正向销售额的百分之多少？」没有定义"退货"。三轮跑出三个答案：7.19%（对）、**4.89%（编造，见复盘 18.4）**、3.72%（口径不同，方法可复现成 3.65%）。所以改成把分子分母分别怎么写全部钉死，并明确"只用发票号前缀区分"（不给模型剔除非商品代码的余地）。

**已知残留歧义（未再修改）**：C 单里有一行是正的（`C496350`，+1 件，373.57），所以"取绝对值"有两种合法读法：

| 读法 | 算式 | 结果 |
| --- | --- | --- |
| 逐行取绝对值再求和 | `SUM(ABS(Quantity*Price))` | 1,466,050.80 → 7.1953% |
| 先求和再取绝对值（标准答案） | `ABS(SUM(Quantity*Price))` | 1,465,303.66 → **7.1917%** |

差额 `2 × 373.57 = 747.14`，换算成百分比差 **0.0036 个百分点**，落在 `tol=0.05` 内，两种都判 ✅（结论正确）。**决定不再改第三版题干**——为一个没答错的细节反复精修，评测集版本会失控。

**这道题能让模型暴露"以为退货就是负数"这个直觉错误。原版 L3-06/07/25 都栽在这个坑上，修正后才有区分度。**

### Q8 · 销售额 TOP 5 商品

**问题**：不算退货和取消单，销售额最高的五种商品是哪几个？各自的销售额是多少？

- **难度**：L3
- **口径**：只算正向、排除 C 单；**排除全部非商品代码**（见第三节清单）；按 `StockCode` 汇总
- **标准答案**：

| 排名 | StockCode | 商品名 | 销售额 |
| --- | --- | --- | --- |
| 1 | 22423 | REGENCY CAKESTAND 3 TIER | 331,084.27 |
| 2 | 85123A | WHITE HANGING HEART T-LIGHT HOLDER | 258,065.91 |
| 3 | 85099B | RED RETROSPOT JUMBO BAG | 180,888.03 |
| 4 | 23843 | PAPER CRAFT , LITTLE BIRDIE | 168,469.60 |
| 5 | 47566 | PARTY BUNTING | 148,395.98 |

- **对账 SQL**：

```sql
SELECT StockCode, MAX(Description) d, ROUND(SUM(Quantity*Price),2) s
FROM orders
WHERE Quantity > 0 AND Invoice NOT LIKE 'C%'
  AND StockCode NOT IN ('M','DOT','POST','BANK CHARGES','C2','D','S',
                        'ADJUST','ADJUST2','AMAZONFEE','B','CRUK','PADS','TEST001','m')
GROUP BY StockCode ORDER BY s DESC LIMIT 5;
```

**陷阱点**：不排除非商品代码时，TOP 5 仍然是这五个（因为手续费金额不够大）—— **所以这题测不出排除清单是否漏项**。真正能测出来的是「平均售价最高商品」，但那题答案太反直觉（手续费），不适合做评测题。**这题测的是"会不会按金额排序而不是按数量排序"。**

### Q9 · 取消订单率

**问题**：历史上被取消的订单，大概占全部订单的百分之多少？

- **难度**：L3
- **口径**：分子分母都按**不同发票数**算，不按明细行数、不按商品数量
- **标准答案**：**15.46%**
- **对账 SQL**：

```sql
SELECT ROUND(
  COUNT(DISTINCT CASE WHEN Invoice LIKE 'C%' THEN Invoice END) * 100.0
  / COUNT(DISTINCT Invoice), 2)
FROM orders;
```

**参考数字**：取消单 8,292 张 / 全部 53,628 张。

**陷阱点**：用明细行数算会得到 `19,165 / 1,044,848 = 1.83%`，差了 8 倍。

## 七、难度分布与评测口径

| 层级 | 题数 | 测什么 |
| --- | --- | --- |
| L1 | 2 | 能不能写出正确的聚合 |
| L2 | 3 | 能不能叠加正确的过滤条件 |
| L3 | 4 | 口径理解：订单 ≠ 行、取消单 = 退货、订单率 ≠ 行占比 |

**评分维度**（建议权重）：

| 维度 | 权重 | 判据 |

**L4 单独判**：说"没有这个信息" = 满分；编数字 = 0 分且标记为幻觉。

## 八、实跑结果（2026-11-12，DeepSeek deepseek-chat）

同一模型、同一批 10 道题，五轮实跑。**判分脚本的输出全部经过人工复核**——原因见复盘 18.2。

| 轮次 | `MAX_STEPS` | 题干版本 | 脚本报 | 人工复核 | 失败题 |
| --- | --- | --- | --- | --- | --- |
| 1 | 5 | 开放式 | 7/10 | 7/10 | Q7 / Q8 / Q9（全撞步数上限） |
| 2 | 8 | 开放式 | 9/10 | 9/10 | Q7（**编造** 4.89%） |
| 3 | 8 | 开放式 | 9/10 | **8/10** | Q4（789，口径不同）+ Q7（3.72%） |
| 4 | 8 | 口径钉死 | 10/10 | 10/10 | — |
| 5 | 8 | 口径钉死 | 10/10 | 10/10 | — |

**关键结论三条**：

1. **`MAX_STEPS=5` 测的是预算不是能力。** 第 1 轮三道失败全是 `sys:到达最大步数限制`；手工提到 8 重跑，三道全部答完且正确（Q7 5 步 / Q8 4 步 / Q9 3 步）。
2. **第 3 轮的 9/10 是假的。** 模型在 Q7 里举了个"如果…会变成 7.2%"的反例，`score()` 把反例数字当成了正答。真实成绩 8/10。
3. **口径钉死后稳定 10/10（跑两次都是）。** 但这是**改题干换来的分**，不是模型变强——所以开放式那三轮的数字必须一起留着。

**已知限制（未修代码，照实记录）**：

- 判分是从自然语言里抠数字比对，**会把模型举的反例算作正答**。本轮靠人工复核纠正。
- Q7 的"逐行取绝对值 vs 求和后取绝对值"两种读法差 0.0036 个百分点，未再精修题干。
- Q8 的 23843（168,469.60）那笔 2011-12-09 大单 **12 分钟后被整单取消**（`581483` +80995 → `C581484` −80995）。按"正数行相加"它排第 4，按"净额"它该归零、第五名变 84879（129,681.08）。**当前只判第一名，所以不影响结果**（第一名 22423 在两种口径下都是第一）。

**评测脚本**：`scripts\11_eval_agent.py`（通用判分 `score()`，规则由 expect 类型决定：`None` = 必须说没有 / `list` = 每项都要对 / `str` = 子串包含 / `int` = 精确 / `float` = 容差 0.05）。加题只改 `QUESTIONS`，`score()` 一行不动。
