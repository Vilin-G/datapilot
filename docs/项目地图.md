> **这份文件解决什么问题**：每次开工只看到"脚下这一小块"，不知道它在整条线的哪个位置、为什么必须做它。

# 一、这个项目最终是什么

**一句话**：用户用中文问一句"上个月哪个国家卖得最好"，系统自己去查数据库、自己算、自己写结论。

**真正的难点不在查数据，在让模型自己决定怎么查。**

**目标岗位**：AI 应用开发 / Agent 方向。
**和项目一的关系**：项目一 LLM Compass = 知识检索 + 问答（RAG）；项目二 DataPilot = 工具调用 + 多智能体协作 + 数据分析。两者合起来覆盖"知识库问答 / 工具调用 / 多智能体"三条主线。

# 二、四环结构：为什么是这个顺序

```
        ┌──────────────────────────────────────────────┐
        │  第四站：服务 + 评测 + 文档                   │  ← 能给人看的成品
        │  FastAPI /ask + 网页 + 10 道评测题            │
        └───────────────────┬──────────────────────────┘
                            │  下层是上层的"能力"
        ┌───────────────────▼──────────────────────────┐
        │  第三站：多智能体决策层                       │  ← 能想、能拆任务
        │  Supervisor 拆任务 → 专员干 → 汇总            │
        └───────────────────┬──────────────────────────┘
                            │
        ┌───────────────────▼──────────────────────────┐
        │  第二站：工具层                               │  ← 能动手
        │  把函数交到模型手里，模型自主调用               │
        └───────────────────┬──────────────────────────┘
                            │
        ┌───────────────────▼──────────────────────────┐
        │  第一站：数据层                               │  ← 有东西可查
        │  数据进库 + 两个查询函数                       │
        └──────────────────────────────────────────────┘
```

**为什么不能倒过来**：

- 没有数据库 → 工具查什么？（所以数据层在底）
- 没有工具 → 决策者调什么？（所以工具层在它上面）
- 没有决策者 → 网页给谁用？（所以服务层在顶）

**这条顺序不可任意调整。** 每往上一站，都是用下一站造出的能力去造新的能力。

# 三、每一站：造什么、为什么需要、什么算完成

## 第一站 · 数据层 ✅ 已完成（2026-09-11 ~ 09-18）

| 项 | 内容 |
| --- | --- |
| **造出来的东西** | 一个能查询的数据库 + 两个函数 |
| **具体产物** | `data/processed/datapilot.db`（表 `orders`，1,044,848 行）+ `get_schema(con)` + `run_sql(con, sql)` |
| **它解决什么问题** | 把 45.6MB 的 Excel，变成"问一句就能答一句"的机器 |
| **验收（已过）** | 手写 SQL 答对 Q1 / Q4 / Q5 → `docs/SQL验收.md` |
| **面试一句话** | "我把数据变成了结构化可查询的形态，并加了只读 + 限行防护" |

**关键事实（随时要能报出来）**：

```
总行数        1,044,848
订单数        53,628          ← COUNT(DISTINCT Invoice)，一张发票 = 一个订单
国家数        43              英国占 91.6%
商品数        5,305
日期范围      2009-12-01 ~ 2011-12-09
```

**两个函数的接口约定**（第二站基于它们造工具）：

```python
get_schema(con) -> str      # 表名 / 行数 / 字段+类型 / 3 行样例，纯文本给模型看
run_sql(con, sql) -> dict   # 成功 {"ok":True,"rows":[...],"truncated":bool,"total":int}
                            # 失败 {"ok":False,"error":"..."}
```

## 第二站 · 工具层 ⬜ 进行中（1/4）

| 项 | 内容 |
| --- | --- |
| **造出来的东西** | 让**模型**会用那两个函数 |
| **具体产物** | 模型能自己说"我要调 `query_database`，参数是这段 SQL"，然后拿到结果 |
| **它解决什么问题** | 模型不会算数、不会 SQL、不知道你的表长什么样。但它**很会读描述、很会做决定**。所以把"查数"包成工具交给它 |
| **验收** | 问"销售额最高的月份"，模型自己查出来，答案 = `1,461,756.25`（2011-11） |
| **面试一句话** | "我不是让模型执行任意代码，而是把它限制在只读 SQL 工具里——这是安全边界" |

**四个小块拆法，每个解决一个独立的难题**：

| 小块 | 解决的难题 | 状态 |
| --- | --- | --- |
| 1 | 模型怎么"看见"工具？（参数表里能填什么） | ✅ 2026-10-26 |
| 2 | 模型怎么"决定"调哪个？ | ⬜ 下一步（卡 API key） |
| 3 | 模型调错了怎么办？→ 错误回传，自我修正 | ⬜ |
| 4 | 模型死循环怎么办？→ 调用次数上限 | ⬜ |

> **小块 3 和 4 才是精髓。** 模型一定会犯错——写错列名、忘加 GROUP BY。
> **一个不会自我修正的 Agent 是玩具。**

## 第三站 · 多智能体决策层 ⬜

| 项 | 内容 |
| --- | --- |
| **造出来的东西** | 一个**主管 Agent** + 几个**专员 Agent** |
| **具体产物** | LangGraph 状态图：Supervisor 拆任务 → 派给 SQL 专员 / 分析专员 → 汇总成报告 |
| **它解决什么问题** | 简单问题（"最高月份"）一个 Agent 够了。但**复合问题**（"对比英德两国利润率，哪个高，为什么"）需要：先查两国数 → 再算利润率 → 再对比 → 再写解释。一个 Agent 干不完，也讲不清 |
| **验收** | 能回答复合问题，且每个结论都追得到具体 SQL 和数据 |
| **面试一句话** | "多智能体不是越多越好——我能量化它的成本和延迟代价，也知道什么时候单 Agent 更合适" |

**这一站才真正需要第二站造的工具。** 现在造的工具，是为第三站准备弹药。

## 第四站 · 服务 + 评测 + 文档 ⬜

| 项 | 内容 |
| --- | --- |

# 五、任务卡的读法（每次开工第一眼看这里）

以后任务卡第一行固定写：

```
【你现在在 → 第 N 站 · 小块 M】目的：一句话
   完成后解锁：下一小块是什么
   在整条线上的位置：它支撑的是哪一环
```

**三个字段各回答一个问题**：

| 字段 | 回答 |
| --- | --- |
| 目的 | 我这一小块要造出什么？ |
| 完成后解锁 | 我做完之后能干什么以前干不了的事？ |
| 在整条线上的位置 | 为什么非做它不可，跳过行不行？ |

**如果这三个字段里有任何一个你看不懂，就是我的任务卡没写清楚——直接问，我重写。**

# 六、时间表与"明确不做"

**大纲预估约 8 天**（实际早已超出，因为第一站补的是 pandas + SQL 从零开始的基础，属于合理超支）。

| 阶段 | 大纲要求 |
| --- | --- |
| 第 1 天 | 数据准备 + SQLite + SQL 工具 → 能手动 SQL 查数 |
| 第 2 天 | pandas 处理 + 工具封装 → 两个可调用工具 |
| 第 3-4 天 | function calling 单 Agent 循环 + 失败重试 + 调用上限 |
| 第 5-6 天 | Supervisor 多智能体 → 能处理复合问题 |
| 第 7 天 | FastAPI + 网页界面 |
| 第 8 天 | 评测 + README |

**明确不做**（大纲原文，别在面试里说漏嘴或自作多情地做）：

- 用户注册与权限系统
- 生产级并发与高可用
- 任意 Python 代码执行（只用只读 SQL，更安全）
- 云端部署（可作为后续可选）
- 复杂报表系统（图表做到基础即可）
